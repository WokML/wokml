1 · Resume launders effects — rung 1 + 2 shipped, inner-abstraction open

The one real soundness-of-the-type-surface hole. A Suspension is "a function you can call to continue" — but a driver that resumes it can silently absorb the parked tail's effects and present itself as pure. The fix is parity: make resuming demand its effects exactly like calling a function does.

program performs a residual row eeven a bare row variable, deep in a coroutine tail
↓ stop silently absorbing it; treat e like any effect row
the enclosing function's row must be >= ethe existing, sound row-unification already does this
↓ so every driver over the tail inherits the obligation
run / step / resume / await gain with eff ecaller needs a handler in scope — just like calling a function value

● today — the type lies (accepted)

-- `run` performs the parked tail's effects `e` on resume...
-- ...but this signature is inferred effect-polymorphic / pure-looking.
replay : Suspension U64 U64 U64 (row e) -> U64
replay g = run g 0     -- the residual `e` is ABSORBED. the type hides it.

● proposed — the type is honest (obligation surfaced)

replay : Suspension U64 U64 U64 (row e) -> U64 with eff e
replay g = run g 0     -- `with eff e` now MANDATORY; callers must handle the tail.

The payoff appears the moment a scheduler exists — it can no longer claim purity while running effectful tasks:

runNext : Queue (row e) -> () with eff e
--                              ^^^^^^^^^ forced: a "pure" scheduler that
--   secretly runs effectful tasks becomes a type error, not a silent hole.

Two shapes were considered; take B, defer C:

chosen · general

B — load-bearing row

Performing a residual row obligates the enclosing row. One localized emitter change, reuses the sound row-unification, and generalizes to Task/Stream/scheduler. Ripples to effect-polymorphic code (a declare-with eff e audit) — the honest cost of honest types.

deferred · coro-only

C — split before/after rows

Two rows on the coro types (effects before vs after a suspend). More precise, makes cancel free — but needs a control-flow-sensitive analysis (not free in HM), changes the coro type shape, and does not generalize to Task/Stream. YAGNI for now.

Shape of the slice: type-only. The change is in the effect emitter — stop absorbing bare row variables. The interpreter is untouched (e stays phantom at runtime), no codegen, no first-class carriers. Visible fallout: coro-resume-driver.wok's golden consciously flips and effect-polymorphic drivers must declare with eff e. Design: docs/superpowers/specs/2026-06-11-resume-site-control-and-heap-continuations-design.md; rung-1 spec: docs/superpowers/specs/2026-07-02-resume-launders-effect-row-loadbearing-spec.md.
Rung 1 → rung 2 (both shipped) → the honest remaining boundary. The original plan assumed one emitter change closes the hole. A review disproved that: effect-row variables carry no provenance, so after a handler discharges its effects, a benign handler leftover tail and a genuinely-laundered residual are the same bare row variable — you cannot tell them apart locally. Rung 1 closed the positions where the residual hits the declared row directly: top-level driver bodies (drive g = run g 0) and resume calls in handler arm bodies. Rung 2 then closed the handler-discharge positions — with H (run g 0), nested handlers, named-instance handlers, and the with s = … in runner-sugar form — with the caller-root provenance rule: a residual obligates iff its tail variable comes from the caller (occurs in the declared param/result types), which a fresh handler-internal tail never does. This replaced rung 1's exempt-by-identity machinery with one positive rule and is airtight by construction (a concrete effect can never be written into a (row e) slot, so a caller-supplied polymorphic row is unhandleable). Those four forms are now death tests in test/typecheck-fail-examples/launder-leak-*.wok. Design: docs/superpowers/specs/2026-07-03-resume-launders-rung2-caller-root-provenance-design.md. Remaining gap (the next slice): the inner-abstraction family — a residual absorbed by a lambda ((\h -> run h 0) g) or a sigless local function (let go u = run g 0 in go ()) before it reaches the enclosing closed row. Different mechanism (effect propagation onto the inner arrow, not provenance); pinned green as launder-leak-inner-*.wok, tracked in docs/superpowers/2026-07-02-lambda-effect-laundering-note.md. Everything shipped is sound — it only adds rejections.

1a · Write vs infer — decided: explicit

Effect rows stay explicit. A missing with means pure, not "infer" — performing an undeclared effect stays a compile error. Inference (Koka-style omit-and-infer) is sound but wrong for wok: it would delete wok's sole effect safety net (the declaration-site check — there is no boundary/main discharge gate) and turn effects from an authored contract into inferred metadata, undercutting the "explicit, controllable effects" thesis. So the law stays uniform: every effect, concrete or polymorphic, is declared.

If verbosity ever bites, the escape hatch is a visible opt-in placeholder — _ in the row tail — never silent inference:

replay : Suspension U64 U64 U64 (row e) -> U64 with eff e   -- explicit (default, the law)
replay : Suspension U64 U64 U64 (row e) -> U64 with eff _   -- opt-in: infer this row from the body

-- a shared input/output row must stay NAMED; `_` fits output/determined positions:
map : (a -> b with eff e) -> [a] -> [b] with eff _

1a — with eff _ still declares "effects flow here" (opt-in, on the page), so the type never lies; it's a middle point between spelling the row out and silent inference. Deferred — ship explicit-only first. Rationale: docs/superpowers/specs/2026-07-02-resume-launders-effect-row-explicitness-decision.md.

✓ Fixed · Conc's phantom residual row

runConc : (() -> a with Conc + eff e) -> a with eff e used to promise the root could perform effects e handled around runConc — but the scheduler (__drive_conc) runs the root and every resume under a fresh KDone, severing the ambient handler frames. So any non-Conc effect handled outside runConc trapped at runtime with NoMatchingHandler. The residual was phantom: type-accepted, unrunnable.

Fix (Option A, implemented on feat/conc-drop-phantom-residual): drop the phantom residual — __drive_conc and runConc become (() -> a with Conc) -> a. An outer-handled non-Conc effect is now a compile-time RowMismatch at the runConc site (like spawn/async children already got), not a runtime trap. Effects handled inside the root still run (the carrier re-installs their handler on resume). Two signature edits, no runtime change, 2118 tests green — nothing depended on the phantom, proving it was truly unrunnable. Deferred (non-breaking): the strict with Conc also rejects a root doing a ground/foreign effect like IO (an in-place call that would run); widening to Conc + ground effects needs a ground-vs-handler distinction — a later follow-up.

3 · Regions can't meet handlers

Function-local arenas (region slice R1) and the FFI borrow tier both disable in any module that contains a handler — the arena/borrow analyses are gated off module-wide when a handler is present. Two foundation features that don't yet coexist per-module. Lifting this is its own slice (arena ↔ continuations interaction), lower priority than item 1.
