# Slice 1: Async effect + deterministic `par` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first structured-concurrency surface — an `Async` effect with a
cooperative `yield`, and a deterministic `par` combinator that runs two children
concurrently and returns both results — expressed entirely as library functions
over the existing coroutine CPS machinery, runnable on today's interpreter.

**Architecture:** `par` is a *built-in driver* (handler) over `Async`, not a new
runtime. A child `() -> r with Async + e` is adapted so `Async.yield` becomes
`Coro.suspend`, run as a coroutine via `start`/`step`, and two children are driven
in lockstep by a recursive two-carrier driver (the `coro-step-zip` `zipSum` pattern
plus result-combination and drain). No new interpreter primitives, no first-class
carriers, no scheduler/IO. Spec:
`docs/superpowers/specs/2026-06-11-async-effect-surface-and-cps-design.md` (Slice 1, §9).

**Tech Stack:** wok compiler (Haskell); the wok prelude (`prelude/Std/Control.wok`);
tasty-golden test fixtures (`test/{typecheck,run}-examples`,
`test/typecheck-fail-examples`, and their `*-golden` dirs); `cabal build`/`cabal test`.

**Key invariants this slice must preserve:**
- `Async` and `Coro` are both *discharged* by `par`; only the children's non-Async
  residual `e` propagates to `par`'s call site (resume-site semantics).
- Deterministic: lockstep left-to-right schedule ⇒ **no `ndet`** in `par`'s type.
- One-shot holds: every carrier is `step`-ped at most once per round; carriers are
  only ever recursive arguments (second-class), never stored or returned.

Append to `prelude/Std/Control.wok` (after the `cancel` definition):
```
-- ---------------------------------------------------------------------------
-- Two-coroutine lockstep driver (slice async-par).
--
-- Runs two coroutines (each `Coro () ()`, i.e. yields/resumes with unit) to
-- completion and returns both results. Carriers are held only as recursive
-- ARGUMENTS (second-class, never stored/returned); each is `step`-ped at most
-- once per round, so one-shot holds. Lockstep (advance both per round) is the
-- deterministic interleave schedule. This is `coro-step-zip`'s `zipSum` shape
-- plus result-combination and per-side drain.
parBoth : Step () () ra (row e) -> Step () () rb (row e) -> (ra, rb) with eff e
parBoth sa sb = case sa of
  Completed ra -> case sb of
    Completed rb   -> (ra, rb)
    Suspended _ gb -> drainB ra (step gb ())
  Suspended _ ga -> case sb of
    Completed rb   -> drainA rb (step ga ())
    Suspended _ gb -> parBoth (step ga ()) (step gb ())

-- drainA: side B finished with result rb; drive side A (the Step) to completion.
drainA : rb -> Step () () ra (row e) -> (ra, rb) with eff e
drainA rb sa = case sa of
  Completed ra   -> (ra, rb)
  Suspended _ ga -> drainA rb (step ga ())

-- drainB: side A finished with result ra; drive side B (the Step) to completion.
drainB : ra -> Step () () rb (row e) -> (ra, rb) with eff e
drainB ra sb = case sb of
  Completed rb   -> (ra, rb)
  Suspended _ gb -> drainB ra (step gb ())
```

FALLBACK (only if Step 4 shows an affine rejection — e.g. `FutureConsumedTwice`
or a carrier-escape on `ga`/`gb`): the driver cannot be a library function under

```
-- ---------------------------------------------------------------------------
-- Async surface (slice async-par). `par` is a built-in DRIVER over `Async`,
-- expressed over the coroutine machinery -- not a runtime (no IO/scheduler).

-- Async: the cooperative-scheduling effect. `yield` is a breakpoint: the task
-- parks and hands control to its driver.
effect Async = { yield : () -> () }

-- asCoro: adapt an `Async` child to a coroutine by mapping `Async.yield` to
-- `Coro.suspend` (yield/resume carry unit). Discharges Async, introduces Coro;
-- the child's non-Async residual e flows through.
asCoro : (() -> r with Async + eff e) -> () -> r with Coro () () + eff e
asCoro c u = with Async { yield x k -> k (Coro.suspend ()) } (c ())

-- par: run two Async children concurrently (deterministic lockstep) and return
-- both results. Discharges Async (and Coro); the children's residual e is
-- demanded here, at the call site (resume-site). Deterministic => no ndet.
par : (() -> ra with Async + eff e) -> (() -> rb with Async + eff e) -> (ra, rb) with eff e
par a b = parBoth (start (asCoro a)) (start (asCoro b))
```
Note: if the op-arm binder `x` in `yield x k` triggers an unused-binder complaint,
rename it (e.g. `yield u k`); unused `let`-binders are accepted elsewhere in the
corpus (`coro-step-zip` line 7), so this is expected to be fine.
