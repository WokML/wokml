# M1.5 — Closures / Higher-Order Functions in the Perceus RC Pass

- Date: 2026-06-14
- Status: design approved (brainstorm), pending plan
- Milestone: M1.5 (RC reference-counting for ordinary closures)
- Supersedes nothing; extends the M1 design
  `docs/superpowers/specs/2026-06-14-perceus-interpreter-static-analysis-design.md`
- Related memory: `rc-perceus-interpreter-plan`, `one-shot-as-law-multiplicity`,
  `higher-ir-direction`, `wok-constructor-naming-convention`
- Out of scope (named milestones): continuation-aware drop / closures captured into
  resumable continuations is **M2**; effect features (`Handle`/`ROp`) stay out of
  coverage; prims-as-first-class-values, list/string `++`, and unboxed value-CAF
  referenced from a function are separate deferrals untouched here.

## 1. Problem

M1 shipped a sound Perceus dup/drop pass (`Wok.IR.Perceus.insertRC`), an explicit-store
RC interpreter (`Wok.Interp.RC.{Value,Prim,Machine}`), and a `balanceLint` audit — but
**only for first-order data**. Closures are walled off on purpose, in four places:

1. `coveredRhs RLam{} = False` — any body containing a standalone lambda RHS is passed
   through `insertRC` unchanged (never instrumented).
2. `ownedOccs` / `moveAtoms` treat an `RLam` operand as a borrow (captures are not counted
   as consumes).
3. `balanceLint`/`lintBind` refuses to certify a covered bind that contains an `RLam`
   ("out of audit scope — closure captures are not modeled"), and the code notes it must
   "learn to model capture-as-consume" before closures are brought in.
4. `firstOrderNoHandlerViolations` (in `Wok.IR.Reachable`) rejects any reachable
   higher-order / handler module from `runModuleRC` rather than leaking.

For `LetRec` the pass *does* cover local mutually-recursive groups, but only when the group
captures **no** enclosing dynamic boxed local — the `Set.null bsc` guard in
`coveredExpr (LetRec …)`. A group that closes over an outer owned value is shoved out of
coverage (passed through, hence un-instrumented and leak-prone).

**Goal:** make `insertRC` + `balanceLint` sound for ordinary closures and higher-order
functions — lambdas that capture owned locals, are passed around, returned, stored,
partially applied, and called (including more than once) — and for local recursive groups
that capture enclosing owned locals, so the boundary guard can stop rejecting them.

## 2. The central question, already half-answered by the runtime

The design tension stated in the M1 notes is: **when is a captured owned variable consumed,
and who frees it?** A capture is consumed when the closure *runs*, not where it is built.

The key finding of this brainstorm is that the **runtime half is already implemented** by
F4 (`cb1d457`) in `Wok.Interp.RC.Machine.enterRC`, and it answers the question cleanly:

- **A closure cell OWNS its captures.** `dropAddr` → `countedChildren` →
  `boxedChildren (NClosure env _ _)` cascade-frees every boxed value in the captured env
  when the cell's refcount reaches zero.
- **Application transfers capture ownership into the running body.** On an exactly-saturated
  call `enterRC` increfs each boxed captured handle (handing the body its own owning copy)
  and then drops the shell:
  - unique closure (`rc == 1`): incref (+1) then the shell free cascades (−1) → net zero on
    each capture, ownership flows into the body scope;
  - shared closure (`rc > 1`): incref (+1) then the shell decrements only → the body gets
    its owning copy, the remaining aliases keep theirs.
- **Partial / over application is already correct** (the `LT`/`GT` branches of `enterRC`):
  a partial application allocates a fresh closure sharing the increfed captures plus the
  supplied args, then consumes the original. The pass needs no special currying rule — at a
  call site it already moves the head `f` and the argument atoms.

So "consumed when it runs" is, at runtime, "released when the cell is dropped, and the act
of running the cell drops its shell." The static pass only has to **mirror a model the
interpreter already implements.**

### Consequences (the prompt's open questions, resolved)

- **Does the cell own its captures?** Yes. Consumed at *build* (moved into the cell, like
  constructor fields); released when the cell is dropped (the cascade). No separate
  capture-lifetime bookkeeping is needed.
- **A closure called more than once?** Allowed, with no special rule. Calling a closure
  consumes one unit of it (the shell drop), exactly as the pass already treats the head `f`
  of `RApp f as` as a move. Two call sites ⇒ two moves ⇒ one inserted dup ⇒ `rc == 2` ⇒
  each call decrements; the captures are increfed per call so each running body gets its own
  copy. Multi-call falls out of the existing dup machinery.
- **Relation to one-shot / affine multiplicity (`one-shot-as-law-multiplicity`)?** That
  analysis governs **continuations only** (the `oaResume` binder). Ordinary closures are
  `Unrestricted` and may be called many times; RC (dup per extra call) handles it. The
  one-shot law does **not** constrain ordinary closures. Continuation capture is M2.
- **How do escaping closures keep captures alive?** By ordinary ownership transfer. A
  returned closure is in the `Ret` result atom (transferred out, not dropped); a stored
  closure is a field move into the enclosing structure. The captures live exactly as long as
  the cell does, because the cell owns them. No new mechanism.
- **A closure built but never called?** The cell dies at its last point of liveness; the
  prompt-drop frees it and the cascade releases its captures. This is the affine
  drop-without-run case (card `Zero`) for ordinary closures — handled by the same drop.

## 3. The unifying frame

> **A closure build is a heap allocation whose fields are its free captured variables —
> semantically identical to `RCon` / `RRecord`.** Build = move the captures in. The closure
> body = its own ownership scope. Drop of the closure = the cascade that frees the captures.

This is the canonical Koka/Perceus closure representation (a closure is a heap object whose
fields are its captured free variables, reference-counted like any constructor). For
*ordinary closures specifically*, wok and Koka agree; the only adaptation required is a
correction to the interpreter's capture set (Section 5). The genuinely wok-specific Perceus
divergences (one-shot continuations, interpreter-first runtime-agnostic placement, deferred
reuse) live in adjacent milestones, not here.

### Free variable vs parameter vs whole-env (the three nested sets)

```
parameters  ⊊  free captured vars  ⊊  whole enclosing env
(never RC'd)    (what we WANT)         (what the interpreter captures today)
```

- A **parameter** is supplied per call; it is never captured (it does not exist when the
  closure is built).
- A **free variable** is referenced in the body, not a parameter and not locally bound; it
  must be captured. The *set* is statically computed (`freeVarsExpr e \ params`); the
  *values* are runtime values from the enclosing scope.
- The interpreter currently captures the **whole enclosing env** — an over-approximation.
  This is the one mismatch M1.5 must fix (Section 5).

For reference counting, only **boxed, owned, non-exempt** free variables matter: unboxed
captures are `RVLit` (never counted), globals are static (negative addresses, skipped by
`incref`/`dropAddr`), and `LetRec` siblings are uncounted-region (skipped by the cascade).

## 4. Phase 1 — Standalone closures (`RLam`)

### 4.1 Capture set — single source of truth

Define the **capture set** of a lambda `\ps -> e`:

```
captures(ps, e) = freeVarsExpr e  \  {ps}
```

The boxed owned captures the pass moves are `captures(ps, e) ∩ delta \ ctxExempt` filtered
to `isBoxedType`. The interpreter restricts its captured env by the same set.

**Correctness-critical:** the pass and the interpreter MUST compute this from one shared
helper, or they drift and reintroduce exactly the project's recurring bug class ("a var
consumed somewhere the placement didn't see"). Today `freeVarsExpr` is private to
`Wok.IR.Perceus` and `Reachable.exprUniques` computes *all referenced* uniques (not free).
The plan will promote a single `freeVarsExpr` (free vars, binders subtracted) into a neutral
module imported by both `Wok.IR.Perceus` and `Wok.Interp.RC.Machine` — mirroring how
`Wok.IR.Reachable` is the single source of truth for reachability. `insertRC`'s existing
`freeVarsExpr` becomes the shared definition (no behavioral change to the pass).

### 4.2 Interpreter change (the one runtime tweak)

In `evalRhsRC`, the `RLam` case currently builds `alloc (NClosure (rscEnv sc) ps e)`. Change
it to capture only the free variables:

```
RLam ps e ->
  let cenv = Map.restrictKeys (rscEnv sc) (captures(ps, e))
      (a, s') = alloc (NClosure cenv ps e) s
  in cont (RVBox a) s'
```

This is **semantics-preserving**: a body can only observe its free vars (plus params and
locals it binds), so rendered output and results are unchanged — the differential oracle
(Suite A) compares output against the reference interpreter and is unaffected. Only which
cells the closure pins changes, which is the entire point: the drop-cascade now releases
**exactly** the set the pass moved in, so pass and runtime agree.

The `LetRec` build path (`evalExprRC (LetRec …)`) is a different construction site and is
addressed in Phase 2.

### 4.3 Pass — build site

- `coveredRhs`: admit `RLam ps e` **iff its body is covered** (`coveredExpr (boxed params) e`
  — so a lambda whose body contains `Handle`/`ROp` stays out of coverage). Because
  `coveredRhs` has no scope argument today, this check is threaded where the scope is
  available (the `Let`/`Case`/`LetJoin` cases of `coveredExpr`, and the new `RLam` body
  scope). `coveredRhs ROp{} = False` is unchanged.
- `ownedOccs (RLam ps e)`: return the boxed owned non-exempt captures as a move multiset —
  identical to `count` over the capture atoms (the same code path as `RCon`/`RRecord`).
- The existing `ownExpr (Let b rhs body)` machinery then handles a closure build with **no
  new code**: `b` (the closure) enters `delta` as a boxed owned value; each capture is
  consumed (moved); a capture that also survives into `body` or is referenced more than once
  gets a dup; a closure that dies in `body` is prompt-dropped (cascade frees captures).

### 4.4 Pass — closure body as its own scope

Instrument the lambda body `e` as a fresh ownership scope, exactly like `onBind` (top-level)
and `onDef` (`LetRec` member):

```
delta0 = { boxed params } ∪ { boxed captures }
ctx0   = env over params + captures, ctxJoins = ∅ (joins do not cross a lambda),
         ctxExempt = ∅
```

The captures are **owned on entry** because `enterRC` increfs them and binds them (with the
params) into the body scope. So inside the body each param and each capture must be consumed
exactly once — the standard scope invariant. Joins reset to empty mirrors the runtime
(`enterRC` runs the body with `rscJoins = Map.empty`).

### 4.5 Lint — model capture-as-consume

- `moveAtoms (RLam ps e)`: return the capture atoms (the boxed owned captures moved into the
  cell), instead of `[]`.
- Descend into the lambda body as a fresh scope (reuse the `lintDef` shape: build
  tracked/exempt from params+captures, walk the body, leak/over-consume checks apply).
- Delete the `exprHasLam` refusal guard in `lintBind` and the corresponding note; the lint
  now *models* the capture instead of refusing to certify it.

The per-`Unique` accounting then balances: at build each capture gets −1 (moved into the
cell) and `b` gets +1 (owns the cell); at `b`'s drop `b` gets −1; the cascade that frees the
captures is modeled structurally (the captures were already relinquished at build, and the
closure body is a separate scope that consumes its own owned copies).

### 4.6 Boundary guard

In `Wok.IR.Reachable.exprScopeFeatures`, stop emitting the `RLam` violation (keep `Handle`
and `ROp` — M2). `firstOrderNoHandlerViolations` then accepts higher-order modules, so
`runModuleRC` runs them on the RC store.

### 4.7 Phase 1 invariant (M1, no borrow inference)

Every boxed free-var capture present in the env is either an **owned local** (counted; moved
by the pass; decref'd by the cascade — they match) or a **global** (static; skipped by both
the pass and the cascade). There are no borrowed boxed locals in M1 (the pass treats every
boxed param as owned; borrow inference P2 is deferred). **Forward-compat note:** when borrow
inference lands, capturing a *borrowed* variable requires a **dup at the capture site** (the
closure needs its own owning unit because it will decref on drop). This is the standard
Perceus rule and is explicitly out of scope here, but the capture-set helper and the build
rule are the natural place it will attach.

## 5. Phase 2 — `LetRec` groups that capture enclosing owned locals

Phase 2 relaxes the `Set.null bsc` coverage guard so a local mutually-recursive group may
close over enclosing owned boxed locals. **A `LetRec` member borrows its captures; a
standalone closure owns them** — this is a genuinely different capture model, which is why
Phase 2 is a second rule, not a reuse of Phase 1.

### 5.1 Why borrow, not own

The region-exempt branch of `enterRC` (`isRegionAddr addr → consume = Right st`) means
applying a `LetRec` member does **not** incref its captures and does **not** drop the shell.
That exemption is load-bearing for recursion: a member calls its siblings on every recursive
step, and per-call incref/drop would over-consume and break the knot. Therefore:

- Inside a member body the captures are **borrowed** — referenced freely, never consumed.
- The **region** owns the captures; the single owning unit per (member, capture) pair is
  released by the group drop's cascade (`countedChildren` of a freed member decrefs its
  non-sibling boxed children).

**Load-bearing assumption — the group drops as a unit at scope exit.** The multiset accounting
(§5.2) balances *because* every member is dropped once at the `LetRec` scope exit, firing each
member's cascade exactly once. This breaks if a member **escapes** the `LetRec` scope (flows
out via the result, or is stored into an escaping structure): the escaped member is not dropped
at scope exit, so its captured enclosing local leaks — and, symmetrically, a sibling dropped at
scope exit dangles under the still-live knot the escaped member holds. This is the Phase-2
analogue of the standalone-sibling hazard in §5.7 (the Phase 1 review finding), and it is the
SAME root divergence: the interpreter captures by lexical scope and defers release to drop-time,
while the pass accounts ownership at build-time assuming a unit-scoped lifetime. **Phase 2 must
therefore handle-or-REJECT (with teeth, like §5.7) a covered group that both captures an
enclosing boxed local AND has a member that escapes the `LetRec` body**; proper support (the
region's lifetime extending past scope exit, the captured local promoted to genuinely counted)
is deferred with the §5.7 representation work. The non-escaping case below is the tractable,
sound Phase 2 win.

### 5.2 Multiset capture accounting at the group build

A capture `y` reachable from `k` distinct members is held by `k` member cells, so the group
drop decrefs `y` exactly `k` times. The build must therefore provide `k` owning units:

```
need(y) = (number of members whose capture set contains y)        -- the multiset count
          + (1 if y survives into the LetRec body)
dups(y) = need(y) - 1     -- y already carries one owned unit from the enclosing delta
```

This reuses the occurrence-counting idea from `ownedOccs`, summed across member bodies. The
captured vars are then removed from the enclosing `delta` (moved into the region) unless they
survive into the `LetRec` body.

With free-var capture (Section 5.4), only members that *actually reference* `y` capture it,
so the multiset count is tight (whole-env capture would charge every member).

### 5.3 Member bodies — captures exempt (borrowed)

Each member body is instrumented as today (delta = boxed params, siblings exempt) **plus the
enclosing captures added to `ctxExempt`** — referenced freely, never moved or dropped. Params
remain owned (the caller moves args in per call). This reuses the existing `ctxExempt`
mechanism; no new body-scope machinery.

**NARROWED (Phase 2 review finding 1, verified double-free).** The borrow model above is sound
**only when every use of a capture is a BORROWED READ** — concretely, a capture occurrence that
is the **scrutinee of a `Case` keeping no boxed child** of it (e.g. `case b of Box v -> v`, which
keeps only the unboxed `v`). A member that **CONSUMES** a capture — passes it by value to a call,
stores it in a constructor/record, returns it, aliases it, captures it into a nested lambda, or
projects it — moves it at runtime (the callee/cell takes ownership and drops it) **while the
group-drop cascade ALSO frees the still-region-owned capture → double-free**. Such a group is now
**REJECTED** (excluded from coverage via the shared `letRecMemberConsumesCapture` predicate, and
refused at the RC boundary), never instrumented. Proper support (dup the capture at the build
site, once per consuming use, so the region keeps its owning unit) is deferred with the §5.7
representation work. The "only borrowed reads" rule is the precise, conservative line: when in
doubt an occurrence is treated as consuming (over-rejection is sound; under-rejection is a hole).

### 5.4 Interpreter change

Restrict each member's captured env to its free vars, in `evalExprRC (LetRec …)`:

```
writeRegionCell a (NClosure (Map.restrictKeys groupEnv (captures(ps, bdy))) ps bdy) st
```

The knot still ties: a member's free vars include the siblings it calls (they are free,
bound by the group), so the restricted env retains exactly the intra-group edges actually
used. `dropAddr`'s same-region skip continues to drop the group as a unit; the only counted
children of a freed member are now its enclosing captures (decref'd) — siblings remain
same-region (skipped).

### 5.5 Coverage relaxation

Replace `Set.null bsc` with: compute the group's enclosing captures and proceed. **Boundary
kept for a later slice:** an enclosing capture that is itself a *region member of a different
group* (cross-region counted edge) is still rejected (passed through). Phase 2 brings only
**non-region enclosing owned locals** (ordinary boxed locals/params) into coverage;
region-to-region capture is deferred (it would require modeling a cascade decref of an outer
region member, which the current `countedChildren` does not skip across regions).

**UPDATED (Phase 2 review finding 2, verified leak).** Coverage *excluding* the cross-region
case was not enough: the RC **boundary guard** (`exprScopeFeaturesWith` in `Wok.IR.Reachable`)
did **not** reject it, so the un-instrumented group ran and **leaked**. The boundary now mirrors
coverage exactly: a `LetRec` whose member captures an **outer** `LetRec` region member
(`rawEnclosingFv defs ∩ enclosing-region-binders ≠ ∅`) is **REJECTED** with a precise diagnostic.
Every program is now either instrumented-and-admitted or rejected-and-not-run.

### 5.6 Lint

Mirror the pass: at the `LetRec` build relinquish each capture `need(y)` times (the moves,
balanced by the build-site dups); add the captures to the body's exempt set inside each
member scope; the group members each enter owned (+1) and drop at scope exit (−1), as today.

### 5.7 REQUIRED — standalone closure capturing a `LetRec` sibling (Phase 1 review finding)

The Phase 1 full-branch review found a **confirmed double-free** that Phase 2 must resolve.
A standalone `RLam` (a `Let`-bound closure, not a group member) that captures a `LetRec`
group sibling is, as of the Phase 1 fix, **rejected** at the RC boundary
(`exprScopeFeatures` in `Wok.IR.Reachable`, see its loud `TODO(M1.5 Phase 2)`) rather than
miscompiled — a sound refusal, not real support.

The hazard: the pass treats the sibling capture as **exempt** (the uncounted region owns it;
the group drop releases it once), so it moves nothing into the closure cell; but the
interpreter captures the sibling's region handle into the closure env, so the cell's
drop-cascade **also** decrefs it. `enterRC`'s incref-on-call cancels that cascade **only when
the closure is called**; on the drop-without-call path there is no incref, so the sibling is
freed twice (cell cascade + group drop) → double-free. Reproducer (verified via
`--dump-rc-stats`):

```
mk u = let f n = case n of 0 -> u; _ -> f (n - 1)   -- f : LetRec member
       in let h = \m -> f (m + 1)                    -- standalone closure captures sibling f
       in 0                                          -- h dropped without being called
main = mk 7
```

A correct fix is region/closure co-design and belongs in this phase (or the slice after it):
the closure representation must distinguish **owned** captures (cascade-free) from **borrowed**
region-sibling captures (do not cascade), AND must handle the **escaping** case — a closure
that outlives its `LetRec` scope forces the captured sibling to leave the uncounted region and
become genuinely counted (it can no longer be released by the group drop alone). This is the
same root divergence as §5.5's region-to-region deferral: the interpreter captures the
unfiltered free-var set while the pass filters by `∩ delta \ ctxExempt`. Phase 2 must either
fully support sibling-capturing closures or keep the boundary rejection with a precise
diagnostic; it must NOT silently re-admit the shape without the representation change.

### 5.8 Phase 2 review findings — two soundness holes, both reject-and-defer

The Phase 2 full-branch review found **two** more confirmed holes, both now closed by the same
reject-and-defer pattern as §5.7 (refuse what we cannot yet compile soundly; defer the proper
fix). Each is verified by a reproducer (`--dump-rc-stats`).

- **Finding 1 — a member CONSUMES a borrowed capture (double-free).** The borrow model (§5.3)
  exempts captures from move/drop, which is sound only for borrowed *reads*. A member that
  passes/stores/returns/calls/aliases/projects a capture **moves** it (the callee or cell drops
  it) while the group-drop cascade **also** frees it → double-free. Reproducer: `letrec go k =
  case k of 0 -> peek b ; _ -> 1 + go (k-1)` over an enclosing `b` (`peek b` moves `b`).
  **Reject:** the shared predicate `letRecMemberConsumesCapture defs bsc` excludes such a group
  from coverage **and** the boundary refuses it ("only borrowed reads are supported"). **Deferred
  proper fix:** dup the capture at the build site once per consuming use (so the region keeps its
  owning unit), with the §5.7 representation work. The borrow-safe line is precise: only a `Case`
  scrutinee keeping no boxed child is a read; everything else consumes (when in doubt → consume).

- **Finding 2 — cross-region capture is uncovered but ADMITTED (leak).** §5.5 correctly excludes
  an inner group capturing an outer region member from coverage, but the boundary guard did not
  reject it, so it ran un-instrumented → leak. Reproducer: nested `letrec`s where the inner
  member calls the outer member. **Reject:** the boundary now computes
  `rawEnclosingFv defs ∩ enclosing-region-binders` and refuses a non-empty intersection, so the
  boundary refuses **exactly** what coverage excludes. **Deferred proper fix:** model the
  cross-region cascade decref (§5.5).

Both predicates carry a loud `TODO(M1.5 Phase 2+)` referencing this spec. The invariant restored:
every program is **either** instrumented-correctly-and-admitted **or** rejected-and-not-run.

## 6. Interactions and non-goals

- **Effects / continuations (M2):** `Handle`/`ROp` stay out of coverage; a lambda whose body
  uses them stays out of coverage (Section 4.3). Closures captured into resumable
  continuations are M2 (the continuation owns the capture and must drop it over the explicit
  CPS form, not the surface CFG).
- **Borrow inference (P2):** out of scope; Section 4.7 records the dup-on-capture rule it
  will need.
- **Prims-as-first-class-values, `++`, unboxed value-CAF from a function:** untouched. A
  lambda referencing a prim by name does not capture it (prims resolve at `callFn`, not via
  the env); a lambda referencing a boxed CAF captures a static handle (skipped). So none of
  these deferrals is pulled in.
- **Reuse / FBIP (P5/P6):** unchanged; insertion-before-reuse ordering holds. Closures are
  just another boxed value the one placement analysis moves and drops.

## 7. Testing strategy

Extend the existing Suites A–F (`test/Spec.hs`, `test/rc-examples/`) rather than inventing a
parallel harness. The triple oracle (differential vs reference + heap-empty baseline +
`balanceLint` balanced, with UAF/double-free trapped by the store) already has teeth; the
work is to feed it closure-shaped programs.

- **Suite A (differential):** add corpus programs exercising — a closure capturing one owned
  local and called once; called twice (forces a dup); returned (escaping); stored in a data
  structure; partially applied then called; built but never called (drop-without-run); a
  higher-order function taking a closure argument; (Phase 2) a recursive group capturing an
  enclosing local; two members sharing one capture. Output must match the reference
  interpreter exactly.
- **Suite B (heap-empty):** each new program must end with `stLive == baseline` and
  `allocs - frees == baseline` — proves captures are neither leaked nor double-freed.
- **Suite C (fault injection, oracle-has-teeth):** confirm the existing mutations
  (`OmitOneDrop`/`OmitOneDup`/`DuplicateOneDrop`) fire on the closure corpus — a missing
  capture dup or closure-cell drop must surface as a leak/UAF/double-free. Add a mutation
  angle if the closure-specific drop (the cell drop that cascades captures) is not already
  hit.
- **`balanceLint`:** the new corpus must lint clean ([]); add hand-built IR regressions that
  reproduce a capture-as-consume miscount (revert-the-fix-reproduces teeth), per the
  project's verified-teeth standard.
- **Suite F (property generator):** extend `genJoinCluster` (or add a sibling generator) to
  emit closures over self-seeded boxed captures — built/called/returned/dropped — and
  (Phase 2) recursive groups capturing an enclosing boxed local. Structural validity only;
  the triple oracle checks the pass. Verify teeth: reverting each Phase 1/Phase 2 fix makes
  the property fail within the first few cases.

## 8. Phasing, success criteria, risks

**Two phases, one session, with a green checkpoint between them.**

- **Phase 1 (standalone `RLam`):** the shared capture-set helper; the interpreter free-var
  restriction; `coveredRhs`/`ownedOccs` build rule; closure-body scope; lint
  capture-as-consume; boundary-guard relaxation. Ship and review before Phase 2.
- **Phase 2 (`LetRec` enclosing-capture):** borrow model; multiset build accounting; exempt
  captures in member bodies; interpreter member free-var restriction; coverage relaxation;
  lint mirror.

**Success criteria:**

1. The full test suite is green at the Phase 1 checkpoint and again after Phase 2.
2. `runModuleRC` accepts and correctly accounts higher-order modules (no
   `firstOrderNoHandlerViolations` rejection for `RLam`); `Handle`/`ROp` still rejected.
3. Every new closure corpus program satisfies the triple oracle (differential + heap-empty +
   `balanceLint == []`).
4. The capture set is computed from exactly one shared helper used by both the pass and the
   interpreter.
5. No change to reference-interpreter behavior or to the M1 first-order goldens beyond
   intended additions; any F4/closure heap-stat golden updated by the free-var restriction is
   re-blessed with the reason recorded.

**Risks / watch-items:**

- **Pass/interpreter capture drift** — mitigated by the single shared helper (criterion 4);
  the highest-leverage correctness invariant in this slice.
- **F4/closure test goldens** — the free-var restriction may change captured-env contents or
  heap-stat numbers for existing direct `enterRC` tests; expect to re-bless with a recorded
  reason, and confirm the change is *tightening* (fewer pinned cells), not a regression.
- **Phase 2 touches the fragile region path** — the project's recurring bug class lives here;
  the green checkpoint after Phase 1, verified-teeth regressions, and the deferred
  region-to-region boundary (Section 5.5) bound the risk.
