3 · What the handle+buffer split actually buys (and costs)

buys

Stable identity on grow

Grow = realloc the buffer, patch ptr/cap in place. The handle’s address never changes, so existing references stay valid. Single-block can’t do this — a bigger cell is a new address.

buys

Isolates the hard part

The handle is always the same tiny size → one arena class, recycled constantly. Only the buffer carries byte-size-class + capacity-rounding. The two concerns stop tangling.

buys

len vs cap = Vec

Capacity slack (cap ≥ len) is the amortized-doubling foundation: push/pop without reallocating every time.

costs

Two allocations

Handle + buffer, vs one block. For a fixed array that never grows, the handle is pure overhead.

costs

Extra indirection

Every index is handle → buffer → element: one more dependent load than single-block’s header-then-slot.

costs

Only worth it growable

The whole point is mutation/growth. An immutable Array gains nothing and pays both costs.

Resolution: fixed Array = single-block (Slice B as planned); growable Vec = handle+buffer (your idea), built on top. The byte-size-class arena serves the variable block in both — the single-block cell, or the Vec buffer.

4 · “Unless it’s a tuple” — sharpened

The thing that forces per-element pointers is not tuple — it is whether the element contains a pointer, and whether the stride is known at compile time. Teardown cost follows the embedded pointers, not the boxed/flat choice.

5 · Where byte-size-class + capacity bites

Granule is 8 bytes; the arena already buckets by word-count (freelist[arity] = (8+8·arity)-byte blocks). So for any block whose size is a multiple of 8, the size class is exact — no rounding, peak_bytes unchanged.

The bite: capacity rounding only changes peak_bytes when the stride is sub-word (Slice D Array Char) or when a coarse large tier rounds. For everything boxed or word-strided, word-count classing is already exact — which is why this rung earns its keep at Slice D, and why the simple recycling win is cheap before then.

6 · The open decision

option A

Two representations

Array single-block + Vec handle+buffer. Each optimal for its use; two layouts to maintain.

option B

Unify on handle+buffer

Everything is a handle. Uniform, but a fixed array pays the double-allocation + indirection tax forever.

option C

Single-block only

Defer Vec entirely. No growable type yet; the handle idea waits.

Lean: Option A — keep the planned single-block Array, add handle+buffer only for the genuinely-growable Vec. Both share the one byte-size-class arena for their variable block. That is the smallest blast radius that still realizes your idea where it actually pays.

7 · Narrowing the scope (decided) — a fixed flat array, not a Vec

Four cuts collapse the design to something much smaller than “byte-size-class + capacity + Vec.” This supersedes the growable-Vec direction above — no handle, no capacity slack.

cut 1

No implicit grow

resize is an explicit op returning a new array (copy-on-write). Removes capacity slack, amortized doubling, and the stable-handle requirement — the address may change because nobody holds it expecting growth.

cut 2

Monomorphic

Element type is concrete → stride known at compile time. The precondition for packing inline at all.

cut 3

Flat / unboxed

Elements packed inline at the stride. One allocation, no per-element header. index copies the bytes out (value semantics).

cut 4

One indirection

Drop the handle. Single-block: cell_ptr (one hop) then + header + i·stride (direct offset). One allocation, one indirection.

The focus moves: the highlighted rung is no longer the handle Vec — it is a fixed, monomorphic, flat, single-block array. The handle+buffer (section 2c) is now rejected for this scope; it returns only if a genuinely-growable Vec is wanted later.

9 · The narrowed layout in memory (Array U64, len = 3)

The array value is a single counted pointer — an 8-byte tagged word (a CAddr) that lives in whatever holds the array (a binding, an enclosing cell’s slot, the environment), not inside the block. Following it once lands on the block: a wide header (rc, a tag marking it a flat array, the stride, the runtime length) immediately followed by the inline elements. 10 · What survives the narrowing (the real remaining decisions)

decision

Where stride lives

Header field (self-describing, simplest) vs an element-kind id indexing a Haskell descriptor (matches the existing ConDescriptor; required once elements hold pointers). Lean: header field for the POD MVP.

decision

Sub-word strides?

Array Char/Bool (stride 1): hdr+N is not a multiple of 8 → rounds up → peak_bytes moves → forces the shared rounded-byte model on both backends. Lean: defer; first cut = word-multiple strides only (exact peak_bytes, no rounding machinery).

decision

Pointer-bearing elements?

POD (Array U64): no embedded pointers → O(1) teardown, no map. Pointer-bearing (Array (U64,String)): per-stride slot-kind map + O(N) cascade. Lean: POD-first.

decision

Abstract-first or C-cell direct?

Model flat on the abstract heap first (mirrors A→B, low risk, gives the oracle a reference) vs build the flat C cell directly (delivers the real contiguity). The contiguity is the point — but abstract-first is the safer oracle path.

Tightest MVP: fixed + monomorphic + flat + single-block, POD word-multiple-stride elements only (Array U64, Array F64, word-sized value structs). Stride in the header. peak_bytes exact, O(1) teardown, no slot-kind map, no rounding. Char/Bool and pointer-bearing elements are clean follow-ons.

11 · “Array in the library” — where the seam falls

The extern keyword is the seam: the library names the type and ops; the compiler/runtime fills the holes. As much as possible lives in .wok; only the raw-memory floor is built in.

prelude/Std/*.wok (real library)

Surface + algorithms

extern type FlatArray a (name + kind); the op signatures; and — if the type system can state “a is sized” — pure-wok derived ops: map, filter, foldl/r, forEach, find, sum, even toList/resize.

Haskell + C (irreducible core)

Bytes + holes

The flat cell (wok_rc.c: wide header + inline elements + size-class placement); type registration + the POD restriction (Types/Builtins/Infer); and the memory-touching primitives the extern signatures point at.

12 · Finding A — scalars are already inline (so flat only pays for structs/bytes)

In wok’s value model, U64/F64/Bool/Char are inline-uncounted values, not pointers. So a boxed Array U64 already stores the integers inline — a “flat” Array U64 would add nothing.

redundant

Array U64

Boxed slot already holds the inline integer. boxed == flat. No win.

flat pays

Array Vec4 (struct)

Boxed = 8B pointer + a separate 40B cell, per element. Flat = 32B inline. 1 alloc vs 1+N; index materializes a cell.

flat pays

Boxed = one 8B word per char. Flat = 1B per char (8× denser). This is the String/Bytes foundation.

13 · Finding B — library-richness is gated by the “sized” constraint

option (i) literal

Hardcoded allowlist

No way to say “a is sized” in a generic signature → ops stay prims; the library is just extern type + signatures. Smallest. Generic pure-wok ops not expressible.

enabler

Sized kind

FlatArray : Sized -> Type, checked at instantiation, no runtime dictionaries (kind-level representation polymorphism). Unlocks generic pure-wok map/fold/toList. More type-system work.

heavyweight

Sized type class

Unbox a => with per-type instances + dictionaries (Haskell-vector style). Most general, but drags in dictionaries the flat array doesn’t need.

Self-describing cells help, but not enough: stride-in-header makes the prims runtime-polymorphic for free; the type checker still needs the kind (or class) to admit generic library functions.

14 · Conclusion — Array a on a real C cell (Slice B)

The codebase findings collapsed the flat/Vector/allowlist plan. wok has only U64/U32 (no sub-word, no floats), and for those the boxed array is already inline — so a separate "flat" type buys nothing today. The real, buildable goal is simpler: stop simulating the array in the interpreter; give Array a a real C allocator cell (the C WokArray Slice A deferred = Koka’s vector). With 8-byte slots it is flat for scalars and pointer-bearing for boxed elements, automatically — so it stays one polymorphic Array a: no rename, no new type, no allowlist.
