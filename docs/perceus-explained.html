How wok's Perceus works

Precise reference counting, drawn out: the compiler decides every count operation, and the runtime just runs them.

The whole system in one line: the compiler decides where every reference-count operation goes; the runtime only executes them and frees a cell when its count hits zero. Everything below elaborates that split.

1Where Perceus sits

The pass runs on ANF, where every value is named — which is what makes "the last use of x" a precise, decidable thing.

2The contract

All the thinking is at compile time. The runtime is deliberately dumb: bump counts, allocate, and free a cell when it dies — cascading to its children.

3The per-variable decision

As it walks the code the pass carries an owned set (called delta in the source). A boxed local joins it when bound, and must be consumed or dropped before the path ends.

That borrow-vs-move split is the single source of truth in the codebase (escapingAtomsRhs in Wok.IR.Escape): the head of a saturated call is a borrow; every other position — constructor field, record field, non-head argument, return value — moves ownership. And one standing rule: a path that ends with x still owned and unused emits a __rc_drop x.

4A worked example

p is used twice, so the pass inserts one dup; the cascade on free does the rest. Watch the count on cell P.

5The twist for effects

The handler work underway changes none of the above. It only changes what counts as a dead cell's children for one new kind of cell — a captured continuation.

Aside · why the owned set deduplicates on (Unique, Addr)

When a continuation is dropped, the same handler-parameter binder can sit in two captured frames at different addresses — the old parameter value (its drop still queued) and the new one (after a set rebinds the slot). Deduping by binder identity alone collapses them and leaks one. The full (Unique, Addr) key is exact: the address distinguishes physical cells, the Unique distinguishes owners (so two binders aliasing one cell, refcount 2, are still freed twice). Reference counting is about cells — and the address is what names a cell.

The takeaway

Keep the runtime dumb — execute counts, cascade dead cells — and push all the cleverness into the compiler's static placement. The entire effects-on-RC effort is just making the one place the runtime computes a child-set (the continuation) match exactly what the compiler's pending drops would have done.
