M3 — stored / escaping continuations

First-class continuations on the RC store, structured so the future compiled backend is a reuse, not a revamp. The cycle is prevented, not collected. The allocator and the runtime are split, and the split is the same one codegen needs.

1 · What M3 is

Today a captured continuation only lives inside its handler's dynamic extent. M3 lets it be moved into a runtime cell, parked, and resumed later — or dropped. Three guarantees re-establish what the handler scope used to give for free, and each is a static proof or a structural fact, never a runtime cycle collector.

2 · The two jobs: allocator vs runtime (and the pass that bridges them)

Three actors, one-way dependencies. The compile-time pass places the ownership instructions; the runtime executes them and makes the dynamic decisions; the allocator is the mechanism the runtime calls. The allocator never knows what a continuation is. This is exactly the separation codegen inherits.

compile time

The Perceus pass

Decides where ownership transfers: places every dup, drop, and move; computes the owned set from the Escape classifier. Runtime-agnostic. This is the asset shared verbatim with codegen.

runtime

The runtime's job

Knows what a continuation, a handler, an effect is. Captures the frame prefix into an NCont; splices it back on resume; computes the owned set to free on drop; resolves which handler an op hits; runs store/take. It decides the moves and calls the allocator. It never manages memory itself.

allocator

The allocator's job

Hands out an Addr (alloc: bump stNext, or reuse from the free list stDead); tracks a refcount per cell (incref/drop); frees and recycles at rc 0. It answers only "where does this live, how many refs, when is it dead." It has never heard of a continuation.

The interface is the whole contract: alloc(node)→addr, incref(addr), drop(addr), deref(addr)→node. Reuse is internal to alloc — a slot freed at rc 0 is handed back out on the next compatible alloc (Perceus/FBIP). The runtime depends on the allocator; the allocator depends on nothing. Swapping the interpreter's IntMap for a native slab changes only the implementation behind this interface.

4 · Why the cycle can't form (prevented, not collected)

A stored continuation could close Q → k → Q only if k holds a counted edge to the very cell it is parked in. Every route to that edge is already blocked:

route by which k could reach its cell Qblocked by
capture the scheduler's run-queuesecond-class handlers — a fiber performs ops against the dynamic stack; it never holds the handler or its queue
capture a promise / channeltoken indirection — those are plain U64 ids, not counted pointers to the cell
embed the continuation in data that loops backthe carrier wall — no NCont in a con / record / env / param slot
smuggle it as a channel payloadpayload restriction + "continuation cannot cross the transport" backstop
reach the store/take cell itselfthe cell is a runtime primitive in the driver scope, not a wok value a fiber can name
The one route that is NOT blocked is making the queue a first-class wok value that fibers capture — i.e. writing the scheduler in wok. That is the self-hosting scheduler (Provider C), and it is deferred. When we build it, the cycle returns and the region/arena answer is real. For M3, it cannot form, so the carrier-wall check (a compile-time predicate) is the whole defense — verified by building the exploit and confirming it is rejected (red-check: drop the check → the leak appears).

5 · The continuation: interpreter NCont ↔ codegen stacklet

The same owned set, two physical encodings. The interpreter is the oracle for the compiled frame.

interpreter (today)

NCont

A linked frame prefix terminated by a splice marker, plus the handler-reinstall info. Captured by moving the above-frames off the Kont. Its owned set is computed on the fly by continuationOwned from the same Escape classifier that placed the drops.

codegen (later, no revamp)

register-spill stacklet frame

A flat heap frame whose fields are exactly that owned set (closure conversion, same classifier). Live scalars inline, boxed children as index fields. The active fiber runs on the C stack; a parked one is this frame. One-shot ⇒ the slot is reused.

The bridge: continuationOwned already returns a flat [Addr] — that list is the frame's field layout. The interpreter's linked prefix and codegen's flat frame are reconciled by the classifier (the single source of truth), so the cache-friendly flat layout is a backend swap, not an interpreter rewrite.

6 · How each piece maps to codegen

The rule: the compile-time pass is identical; the runtime's dynamic decisions become static structure; the allocator keeps its interface and grows a real layout.

What "no revamp" means concretely: codegen does not re-derive what the interpreter was secretly doing. It takes the Perceus pass unchanged, reads the owned set as the frame layout, reuses the affine decision as contify-vs-reify, and replaces the only genuinely dynamic thing — handler resolution — with evidence passing. The interpreter's dynamic work (capture-from-frames, findHandler) is precisely what compilation turns into static structure (closure conversion, evidence).

7 · Slices and what stays deferred

M3-a

the affine analysis

Prove single-take on the cell handle. The long pole; red-checkable; it is the contify-vs-reify decider. Static, runtime-agnostic.

M3-b

the cell + checks

store/take primitive, the carrier-wall check, drop/finally. Oracle: store-then-resume heap-balanced; dropped-unresumed runs finally + frees once; cycle exploit rejected.

M3-c

a thin harness

A minimal run-queue handler exercising the primitive end-to-end, oracled against the reference driveConc.

Deferred and pinned: the full Conc port, the self-hosting wok scheduler (Provider C — where the cycle returns), and the region/arena layer (a codegen-time performance structure, never a soundness one). One-shot stays the law; multi-shot stays a compile error.
The point: the interpreter is both the runtime and the oracle. M3 keeps the allocator/runtime split clean, proves at-most-once and cycle-freedom statically, and lets drop run finally — so the eventual codegen builds the continuation at compile time and reuses the same ownership decisions, rather than re-discovering them.
