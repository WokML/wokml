Borrowership in wok — coarsest to finest granularity

A data value is always in one of two states: owned (someone is on the hook to free it) or borrowed (it rides inside someone else's lifetime, so nobody here must free it). "Borrowership granularity" = how finely the system tracks a value's real lifetime to decide which. Finer tracking means less reference-counting traffic and more escapes handled cheaply — paid for with more analysis. wok climbs this ladder; it stops, on purpose, one rung short of Rust.

Effects decide WHERE a value lives; RC decides WHEN it dies. Borrowership is the seam between them — it says whose lifetime a value rides on.
Coarse = cheap analysis, more RC traffic + leak-till-scope-exit. Fine = less traffic, more analysis. Each rung trades one for the other.

Each rung, concretely

baseline L0 · coarsest

Own everything

No borrow concept. Every shared use inserts a dup; every owner a drop. Correct but maximal RC traffic. This is what borrowing removes — the "before" picture.

wok never sits here: it has at least L2 by default.

built L1 · whole program

Immortal / static

A top-level CAF lives the whole run. It is borrowed by all, owned by none, never counted — the coarsest verdict, fixed once at its allocation site.

Static immortal region; negative Addr; isUncounted makes dup/drop no-ops (arc §3).

built · default L2 · per call, uniform

Uniform borrow-on-call

One fixed syntactic rule, applied at every call: the value in the head of a saturated call is borrowed (calling it doesn't consume the closure); arguments are owned/moved. No per-value reasoning — the rule is the same everywhere.

escapingAtomsRhs (head exempt), consumingOccs (head exempt). The standard Perceus borrowed-head heuristic.

baby built · epic L3 · per scope cohort

Region / arena

A cohort of values shares one lifetime: born together, freed wholesale at scope close, with intra-region back-pointers uncounted (borrowed within the region). No per-cell counting; O(1) bulk free instead of O(N) drops. Costs: leak-till-scope-exit for churn; escape breaks it.

analysis built · routing planned L4 · per value @ scope boundary

Escape-driven promotion

Now each value in a scope is judged individually: if it does not escape, it stays borrowed at region-lifetime (cheap); if it escapes, it is promoted to its own counted lifetime, driven by its refcount instead of the scope. Recovers skip-RC speed for locals and lets values escape — no copy-out, no compile error. This is "finer borrowership via scope."

BUILT: the escape analysis (Escape.hs: escapesFrom, letRecEnclosingCaptureEscapes). PLANNED: the promotion / R+escape allocation-site routing (M2a-2 §4.2; arc §5 "R + escape").

deferred L5 · per use, inter-procedural

Borrow-passing

The finest sound borrowing without types: each occurrence is borrow-or-consume, and a borrow can be passed through a call — the callee borrows a parameter (doesn't consume it) and hands the borrow back. Minimal dup/drop. This is the "proper" fix the consuming-capture class is waiting on.

NOT BUILT. Escape.hs FINDING 1: "the properly-sound mechanism is borrow-passing (the callee borrows)" — a later slice. Would clear the deferred #1 consuming-capture rejections.

rejected ceiling L6 · per reference, typed

Lifetime-in-types

The finest possible: every reference carries a named lifetime the type checker verifies (&'a T, region polymorphism Array r a, the rank-N ST trick). Zero runtime cost — but a heavy type-system + ergonomic burden.

DELIBERATELY REJECTED. The region deep-research verdict (arc §6): wok wants second-class + escape analysis, NOT lifetime-in-types. This rung defines where wok stops.

The crux mechanism (L3 → L4): escape decides borrow vs own

This single fork is what "finer granularity via scope" means in practice. A value born in a region reaches the scope boundary, and the escape analysis routes it:

value born in a region { } scope
↓   at scope close, does it escape? (Escape.hs)
NO → stays BORROWEDregion-lifetime · uncounted · freed wholesale (0 RC traffic)
YES → PROMOTED to OWNEDits own counted lifetime · born in the RC heap · no copy-out
Why this is wok-native. The escapee is born in the RC heap (routed there up front), so there is no copy-out walker and no soundness proof to invent; the local stays in the cheap arena. wok already ships the escape analysis (Escape.hs) and the region runtime (stRegionOf + the M2a-2 promotion shape) — the missing pieces are the runtime arena primitive and the IR-level alloc routing. The three coarser models are special cases of this one: F = "escape is a compile error" (never promote); R = "always counted" (never borrow into the arena); R+escape = this fork.

Does any of this change the surface language?

No new grammar is required — the core is pure compiler analysis. Borrowership is "lifetime as analysis": the programmer writes ordinary wok, and the compiler decides owned-vs-borrowed and where each value lives, invisibly — exactly like Go's stack/heap split or ML Kit's inferred regions. The only rung that would force new surface syntax is the one we reject.

levelsurface impact
L1 immortalnone — compiler-internal (static allocation site)
L2 borrow-on-callnone — pure Perceus analysis
L3 region / arenanone required. Attaches to scopes that already exist (function bodies, let blocks, handler extents). An optional programmer-visible arena rides the existing with…in effect-handler grammar (a provider effect, like State) — not a new keyword. A brand-new region { } block is possible but unnecessary.
L4 promotion / R+escapenone — allocation-site routing is invisible (the Go / Tofte–Talpin "lifetime as analysis" model)
L5 borrow-passingnone if inferred (Koka infers borrowed parameters with no annotation). A ^/& marker only if we chose explicit — we would not.
L6 lifetime-in-typesrequires new surface (lifetime params 'a, region variables). This surface + ergonomic burden is a core reason it is the rejected ceiling.

The whole design is built to keep the surface clean: even resource cleanup is RAII-via-type + a library close (M2 spec §7.4/7.5), never a new try/finally keyword. "Reject lifetime-in-types" (arc §6) is, in part, a decision to never push lifetimes into the syntax.

What I propose

Treat the regions epic as climbing this ladder — one shippable rung at a time, never skipping to L6. We are solid through L2 and already own a baby L3 and the L4 analysis, so the epic is short and each rung is independently sound and measurable (the differential oracle counts the dropped frees + lower peak).

Two forks still open for you — neither needs new grammar.
1 · Visibility. Regions can be fully invisible (compiler-inferred, Go-style — the programmer marks nothing) or opt-in via the existing with…in effect syntax (a provider effect — visible, but still no new keyword). A brand-new region { } block is the one option I'd avoid, since it adds surface for no gain.
2 · Escape. F (escape = compile error — simplest to build, but the harsh error really wants an opt-in marker to justify it) vs R+escape (escapees silently routed to the RC heap — graceful, no errors, no need for any marker, and the most "lifetime-as-analysis"). Note the pull: no-surface favours R+escape, because invisible regions that throw unannotated escape errors are bad UX, whereas invisible R+escape just works.
Either way R1 builds the arena runtime first (shared plumbing). My refined lean: invisible/inferred + R+escape as the north star, reached either in one slice or via an F stepping-stone — your call on visibility decides which.
